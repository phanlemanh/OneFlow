--- Root cause found ---
node_modules in this worktree resolves via symlinks that point OUTSIDE the repo, into an
ephemeral temp directory that no longer exists:

  node_modules/puppeteer-core -> ../../../../../private/var/folders/9d/08v498213jd2lcnpvdlky46m0000gn/T/tmp.uPqC6LLT7g/agk-baseline/node_modules/.pnpm/puppeteer-core@25.4.0/node_modules/puppeteer-core

Same broken pattern confirmed for next, react, react-dom, @xyflow/react, lucide-react —
i.e. the ENTIRE node_modules tree, not one package. The temp dir
/private/var/folders/.../T/tmp.uPqC6LLT7g/agk-baseline/ is now empty (confirmed via `ls`),
so every module resolution in this checkout is broken.

This explains the 404s: the already-running `pnpm dev` server (pid 33742, started before
the corruption) had already-compiled chunks cached, so the very first `curl /workspace`
in this session returned a fully working page (used for evidence/E4-step1.png). But
Next.js dev compiles route bundles on demand, and once node_modules broke mid-session,
any request needing (re)compilation of main-app.js / workspace/page.js / their CSS
started 404ing — every subsequent load, including fresh navigations from an isolated
browser tab (tab-5).

Practical effect: client-side JS never hydrates on /workspace anymore. Confirmed directly:
clicking the "add image" toolbar button (SmartIsland's IconButton, onClick ->
addNodeAtViewportCenter({type:"addImageNode"}) -> addNode(...)) has zero effect —
document.querySelectorAll('.react-flow__node').length stayed 0 after both a synthetic
mouse click and a direct element.click() call, because there is no live React tree to
handle the event (no page.js/main-app.js loaded).

This is NOT a defect in the add-media-library feature (AC-2) itself — it is shared-tree
corruption from a concurrent peer session. `git status --porcelain` on package.json /
pnpm-lock.yaml shows no diff; I did not touch node_modules, and did not run any install.
ListAgents shows 5 active peer sessions on this machine; one peer's browser tab (tab-3,
not touched by this verification after discovery) was independently navigated to
/proto/add-media-library?state=unranked mid-session, consistent with a concurrent
acceptance/design-pass process against this same shared checkout.
