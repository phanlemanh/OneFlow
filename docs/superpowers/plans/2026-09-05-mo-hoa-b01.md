# Mở hoá B01 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hạ cánh nhánh `b01/open-source-rebrand` (đã gộp `main`), trả ba khoản nợ nhánh bỏ sót, và đặt một guard có răng trong CI để định danh của fork không trôi ngược về upstream.

**Architecture:** Một guard bash `scripts/fork/check-fork-identity.sh` quét lớp định danh upstream trên bộ file khai trước với bản miễn trừ khai trước (bánh cóc hai chiều) cộng các khẳng định dương có tên; một script răng 27 ca phá-đúng-một-biến; hai script phụ (làn prototype, suite key); dây vào job Acceptance Gate và guard-của-guard. Tài liệu sửa tối thiểu để guard xanh.

**Tech Stack:** bash + grep/sed/awk, python3 (đọc YAML/TOML), GitHub Actions.

**Spec:** docs/superpowers/specs/2026-09-05-mo-hoa-b01-design.md · Hợp đồng: `_acceptance/mo-hoa-b01/contract.md` · Ô đo: `_acceptance/mo-hoa-b01/evals.yaml`

- Không sửa guard của hồ sơ khác trừ `scripts/ci/check-gate-guards-job.sh` (thêm needle, khuôn AC-9 lat-cat-chung-minh).
- Comment trong code: tiếng Anh. Thông điệp guard in ra: tiếng Việt có dấu, ghim đúng token trong evals.yaml.

- Thứ tự: guard ĐỎ trước (Task 1 chạy trên cây hiện tại phải đỏ đúng ba khoản nợ), sửa tài liệu sau (Task 2), rồi răng.

- [ ] **Step 2: Viết guard** (bash, `set -euo pipefail`, grep không `-q` trong pipeline). Cấu trúc:
  1. Đọc `ROOT`; danh sách `FILES` khai trước; file nào thiếu → `echo "FAIL: thiếu <file> — không kết luận"` exit 2 (riêng `.github/FUNDING.yml` phải VẮNG).
  2. Đọc `repo=` từ conf; `OWNER_REPO_LC` = chữ thường; `IMAGE="ghcr.io/$OWNER_REPO_LC"`; `DIST` = `[project] name` từ `sdk/pyproject.toml` (sed). Nếu `git -C "$ROOT" remote get-url origin` trả về URL → rút `owner/repo` (bỏ `.git`), so không phân biệt hoa thường với conf; lệch → `FAIL: conf lệch remote — conf=<a> remote=<b>`.
  3. Lớp regex `PATTERNS` (8 mẫu đúng design §5). Với mỗi file, mỗi mẫu: `grep -nE` → mỗi hit (file, dòng, mẫu) phải khớp ≥1 dòng allow cùng file mà regex allow khớp dòng đó; không → `FAIL: định danh upstream ngoài miễn trừ — <file>:<dòng>`. Với mỗi dòng allow: đếm hit thật; 0 → `FAIL: miễn trừ ôi — <file>|<regex>`.
  4. Khẳng định dương, mỗi cái một `OK:`/`FAIL:` với token đúng bảng design §6 (`ảnh container` · `compose thiếu build:` · `<README> thiếu chuỗi ảnh` · `<README> thiếu docker compose up -d --build` · `desktop-release còn trigger tags` · `desktop-release prepare thiếu if tags` · `desktop-release thiếu header DISARMED` · `Release checklist thiếu Not currently released` · `Release checklist nói ngược hành vi` · `FUNDING.yml còn đó` · `<template> không trỏ fork` · `CONTRIBUTING.md không trỏ fork` · `badge stars/release còn ở <README>` · `<README> thiếu badge CI của fork` · `badge PyPI không trỏ <DIST>` · `NOTICE không nêu <DIST>` · `NOTICE còn consumed unchanged` · `ghi công upstream còn ở NOTICE.md`).
  5. In `miễn trừ tối thiểu:` ba dòng (NOTICE ghi công, desktop-release app.tongflow.com, desktop-release TongFlow-) — FAIL nếu một trong ba vắng trong allow.
  6. Tổng kết, exit.
